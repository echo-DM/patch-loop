# 01 — 永久 Provider 错误直接结束运行

**What to build:** 明确每日额度耗尽、参数/鉴权/权限/模型标识错误及未识别异常不再重试；暂时错误保留恢复资格，失败报告记录最后一次错误。

**Blocked by:** None — can start immediately

**Status:** ready-for-agent

- [ ] 识别已确认设计中的暂时性连接错误、超时、HTTP 408、原因不明的 429，以及暂时性 500/502/503/504；这些错误保留 Provider retry 资格。
- [ ] 永久客户端错误及其他未识别异常只尝试一次；确认的 Daily quota exhaustion 立即结束，并给出稳定、可操作的说明。
- [ ] Daily quota exhaustion 只依据受识别的结构化每日额度标识判断；仅凭 429、RESOURCE_EXHAUSTED 或异常文字不能判定每日额度耗尽。
- [ ] 在 SDK 包装异常及异常链中提取有界、规范化的失败元数据；原始异常、响应和凭证不进入模型上下文、报告或日志。
- [ ] 连续两次不同的 Provider 失败最终报告最后一次错误，而不是第一次；稳定错误分类与现有终态约定保持兼容。
- [ ] 编辑后遇到不可重试错误时，最终结果为 failed，无发布意图和返回补丁；不进入保留部分补丁的预算耗尽分支。
- [ ] 保持 SDK 自动重试关闭，现有暂时性错误恢复与消息回滚路径仍可用；所需类型调整随这一行为一起交付。
- [ ] 使用假响应覆盖上述完整运行路径，聚焦离线验收与严格类型检查通过；同步更新权威 Gemini 行为说明。
